# 持续优化记录

优化方向：在满足课程要求的前提下改进产品，沿用用户允许扩展功能的授权。本文件记录每轮实际结果，不把一个版本发布当成课程工作已全部完成。

## 2026-09-08：v0.2

上一轮分类：**进展**。重新检查代码库后，确认 v0.1 已保存提交 `11c054b` / `8ac3403`，包含可运行工具与受控案例。本轮以这些实际文件为起点。

### 改进了什么

- **纠正课程映射**：课件要求四个技术组中至少三个；TF-IDF 和决策树不能算成两个组。现在以规则推理、知识发现、证据知识图谱三个组组织实现与展示，详见 `COURSE_ALIGNMENT.md`。
- **处理测试执行失败**：新增 `pass_tests` / `pytest_run`；记录 setup/call/teardown、断言类型、结果计数和选中节点。原有默认收集入口保持轻量。
- **精确验证**：只重跑已观察失败节点，可以关闭明确执行通过的对应问题；其他问题保留。跳过、xfail、删除或未执行的节点不视为已修复。相同组部分重跑保留未覆盖成员，完整检查更新成员。
- **隔离环境证据**：相同报错在不同解释器中不会覆盖旧记录；旧环境的未解决问题保留，但不生成针对新环境的修复建议。
- **可查询的知识图谱**：7 类实体、10 类有类型关系，连接目标、行动、事实、问题、事件、证据位置与检查。`ask` 提供受控中文查询，`graph` 导出 JSON，HTML 可选择实体查看来源路径；没有从相似度生成因果边。
- **改进实验真实性**：新增执行故障套件，同一工具内的独立错误有单独分组标签；移除了旧的固定检查次数模拟。训练器支持 12 特征模型，保留旧 8 特征模型读取能力。
- **改善阅读**：失败测试使用简短节点标题，完整 traceback 保留在证据里；窄屏状态标签不再随长标题拉伸。

## 2026-09-08：v0.3 三轮优化

### 第一轮：具体到项目声明的建议

增加 `project` 只读检查，读取 pyproject.toml、requirements（含项目内递归引用）及 setup.cfg。按目标解释器的版本和 marker 环境判断必需、可选和条件依赖；不把宿主环境拿来判断目标。建议包含来源、包名、约束和安装版本，文件哈希与证据关系可查询。项目检查自动刷新环境，陈旧快照不提供当前声明结论；只删除或放宽声明不能关闭原问题。

### 第二轮：官方历史缺陷复现

新增 Packaging #788 / #678、Click #2500 / #2632 四个最小复现。官方 wheel 的版本、来源、SHA256 和许可证随包保存。每例单独创建环境，离线安装故障版本、实际失败、切换官方修复版本、实际通过，测试源码哈希不变。它们来自两个第三方库，不冒称四个独立完整项目；不是原 CC0 数据。额外声明冲突演示复用已计数的 Packaging 缺陷，不增加自然缺陷数。

### 第三轮：利用真实输入修正诊断与呈现

真实 `InvalidVersion` 案例暴露了按名称后缀和 traceback 文本猜异常的不足。现在记录实际异常类型、消息及抛出位置，摘要从 1874 字符变为 42 字符，完整 traceback 保留。保护 pytest 收集包装异常；不会把断言文字里提到的 ModuleNotFoundError 当作实际导入失败。结构化脱敏保留 JSON，易变对象地址可归一化，版本、路径、模块与实际十六进制值保留区分。

旧 Gini 模型在四例中误判一条普通运行异常。保留准确率 75%、Macro F1 0.333 的结果，界面明确提示候选分歧，行动不受错误候选驱动。没有导入问题时去掉泛化的导入建议；声明不满足时先核对明确的运行要求，再重复验证，不声称该声明就是断言失败的根因。

## 2026-09-24：v0.4

上一轮分类：**纠正**。复查发现 v0.3 的决策树特征就是 parser 已经算出的类别（标签泄漏，F1=1.0 没有意义）；前向推理只有单跳规则，行动写死在代码里；知识图谱不含领域知识。

### 改进了什么

- **任务重定义**：从"复述 parser 类别"改为"判断根因"（五类），这正是同一异常需要不同处理的地方。
- **规则引擎**：变量绑定、分层否定、版本比较、结论溯源；规则移到 `knowledge/rules.toml`，共 56 条，分四个阶段。
- **领域知识库**：117 个已移除名称（附版本、替代写法和来源）、导入名映射、异常类型对应的候选原因；规则直接查询。
- **决策树**：44 个原始证据特征，在 215 个真实执行案例上训练，只在规则无法判断时作为假设使用。
- **实验**：留一模板和留一场景两种交叉验证，加上基线、消融和 bootstrap 置信区间。混合方法在"没见过的故障类型"上准确率 0.930，v0.3 基线为 0.419。
- **界面**：全英文；新增本地 Web 界面（令牌校验和 Host 校验）以及练习场演示。
- **修复的 bug**：`random.py` 等同名文件导致环境快照失败；完整运行后旧的收集错误无法关闭；pytest 打印的 `os.environ` 被写入记录。

### 本轮验收

101 项测试通过，ruff 通过；诊断数据集 215/215 复现；四个上游回归和依赖演示离线复现成功；示例产物检查过没有本机路径。在 Web 界面上完整走通了练习场流程。仅在 macOS Apple Silicon、Python 3.12 上实机验收。

## 2026-09-24：v0.5

上一轮分类：**扩展与纠正**。v0.4 的指标全部来自合成数据；拿真实开源项目检验后，暴露出大量合成数据里没有的问题。

### 改进了什么

- **界面**：纯工具界面；必须修与可选（不影响运行）分开，顶部只统计必须修的问题；安装建议附可复制命令；首页和目标选择加了说明。
- **Windows**：进程树终止、文件锁、路径与编码、启动脚本。
- **真实项目发现的诊断缺口**（humanize、Flask 1.1.4）：conftest 失败、pip check 与缺失名称的联系、库内部使用的已移除名称、缺 pytest 插件、测试计数的警告被环境打乱、Ruff 结果按风险分级。
- **留出检查**：13 个没用过的项目（9 个领域、Python 3.9–3.14），先标注后运行。第 1 轮 2/13 正确；FixFirst 自身的兼容性问题（Python 3.9、pytest 9 子测试、未激活环境）、不读 setup.py 和 flit、建议 pip 安装 Python 等都是普遍原因，修复后第 2 轮 9/13。
- **版本搜索**（`versions.py`）：在临时环境中按版本系列试装（倍增步长后二分，最多 12 次，只装 wheel），给出仍提供某名称的最新版本；**锁文件**给出项目测过的版本。第 3 轮 12/13（后两轮不算留出）。
- **修复的 bug**：只运行单项检查时，其他工具的问题被误标为“待重新检查”；一个缺失名称被算成多个问题；headline 按步骤而不是按问题计数。

### 本轮验收

132 项测试通过，ruff 通过；诊断数据集评估与 v0.4 逐项一致（metrics、predictions、决策树相同）。13 个留出项目三轮结果和两次标注更正见 `docs/GENERALISATION.md` 与 `examples/real-world/LABELS.md`。Windows 实机测试待完成。

## 2026-09-24：v0.6.0 代码审查后的修复

- **Ruff 验证状态**：空 JSON 结果与非零退出码冲突时，按工具失败处理；解析成功并通过一致性检查之后才标记覆盖完整。旧问题保持未验证，不再被误判为已修复。
- **版本搜索**：候选包含当前系列的早期补丁版；倍增、二分未找到结果时，用剩余预算检查遗漏的补丁版。仍最多试装 12 个版本；没查完或有版本无法安装、导入时，不能断言旧版本都不提供该名称。
- **安装建议**：固定到实际试装并确认导入成功的版本（`==`），不再用可能装回故障版本的上界。找到可用版本不代表证明它是最新可用版本，也不能替代项目测试。
- **说明同步**：更新 README、架构及课程技术映射；历史第 3 轮结果保留，并注明当前行为已修正。
