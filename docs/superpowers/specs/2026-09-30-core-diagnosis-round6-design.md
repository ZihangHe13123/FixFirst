2. 重训决策树：不能修复安装指令、版本搜索范围和 CLI 状态，本轮不以替换模型作为目标。

## 设计

### 1. 依赖约束与版本搜索

- 增加小型依赖计划模块，统一读取目标解释器快照中的 Requires-Dist、项目 required/constraint 声明和目标 marker；不使用宿主机器的 marker 默认值代替缺失信息。
- 返回每条约束的来源。已安装包、声明或解释器约束发生变化后，旧搜索的可行性必须重验，不能只根据目标包版本复用结果。
- 升降级动作先交集检查。固定版本与所需修法矛盾时，指出具体固定版本/依赖来源，移除不可执行的命令，提出调整声明或重新建立兼容解释器环境的步骤。不能默默无上限升级。
- 缺少名称不证明名称已被删除。若当前版本不满足已安装依赖的下限，优先满足该约束；没有历史证据时使用中性措辞，不直接声称“no longer provides”。
- 版本搜索只试满足声明、已安装依赖要求、Requires-Python 和 wheel 条件的候选。API 存在、安装成功、依赖一致性和项目整体通过分开记录；无可行候选、预算用尽和网络失败分开。
- 搜索仍是用户主动调用的检查，只在临时环境安装 wheel，保留次数和超时上限，不修改目标环境。

### 2. 安装计划与失败证据

- 对多个缺失的已声明必需依赖，生成一次安装/解析的计划，保留版本限制，避免每次只处理一个模块。可选组不默认启用，URL、路径、未知语法不转成猜测的 pip 参数。
- 从导入的 pip 日志识别构建失败的包、找不到可安装版本、Python 版本不满足及 resolver 冲突。保留日志来源和局限；导入日志不证明当前环境状态，也不能关闭当前失败。
- 安装失败有具体包和对应固定版本时，先说明阻塞项及应该修改的声明，不重复推荐已知失败的安装步骤，不凭一个编译错误断言所有版本均不支持该 Python。
- 静态读取 `environment.yml` / `environment.yaml` 的 dependencies 与 pip 子列表，保留 conda/pip 来源。支持安全的字符串子集，未知构建/channel 语义明确保留未知。Conda 包名不能一律当成同名 PyPI 包；跨管理器的安装只使用有依据的映射。
- `pandas.concat` 等已有源码迁移建议保留；未验证可安装的旧版不作为肯定可行的备选。缺 wheel 与完全不支持 Python 分开表达。

### 3. 当前动作与历史记录

- 诊断和安装计划只采用当前解释器/检查范围内的 open、awaiting_verification 问题。not_observed/unknown 历史继续保留，供重跑验证，但不重新套用当前版本生成旧的错误结论。
- CLI 展示与网页使用相同的步骤选择、排序和折叠；过时检查动作不能通过旧 ID 再执行。CLI 保留明确的重新检查入口。

## 依据

- pip 的 resolver 会同时考虑本次安装请求的依赖；这不等于任意单包安装命令保证原项目全部兼容：[Dependency resolution](https://pip.pypa.io/en/stable/topics/dependency-resolution/)。
- requirement 的名称、范围、marker 和 extras 按标准解析：[Dependency specifiers](https://packaging.python.org/en/latest/specifications/dependency-specifiers/)。
- environment.yml 区分 Conda dependencies 和 pip 子列表：[Conda environments](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html)。imageio 的两种安装名由其官方说明支持：[imageio installation](https://imageio.readthedocs.io/en/stable/user_guide/installation.html)。

## 交叉验收后的具体化（9db099d 之后）

Claude 将 A2、C、D2b 分别评为需要操作者选择版本的部分建议，不能计为成功。补充的核心诊断步骤如下：

- 提供显式 `dependency_resolve` 检查。用户主动选择后，使用目标 Python 新建临时环境，试着放宽**被点名的一个包**的版本声明；其余项目要求和依赖图之外的已安装包版本保留；根据目标环境的 Requires-Dist/markers/extras 识别间接依赖，允许相关的间接依赖共同更新。让声明中的依赖共同解析，旧版依赖自身的元数据不阻止它被一起更新。
- 只安装 wheel；总预算不超过 300 秒；完整记录安装失败/超时与依赖一致性检查。未知、动态或 Conda 专有声明不被静默遗漏。
- 成功仅表示安装与 metadata 一致性已验证。输出具体声明位置、原要求、建议精确版本、整组安装版本；清楚标注原程序/测试尚未验证。用户先审阅修改声明，再手动安装和运行原检查。FixFirst 不修改原文件或环境。
- 失败保留 resolver 输出，不重复同一轮降级/升级。README、.python-version、runtime.txt 中的 Python 版本只作为带行号的文档线索；可用性只引用实际查询的 uv 本地目录，不承诺下载一定成功。
- `environment.yml` 的映射扩展到 SciPy、scikit-learn、matplotlib、pandas、Pillow、joblib，来源为各项目安装文档及 Conda feedstock；不支持的管理器项仍明确展示。

新增检查仍属于已有的受用户触发的安装试验，CLI 和网页共用动作。暂不扩大 MCP 工具协议；完整诊断仍能展示步骤，facts 模式保持不含建议。

Claude 在 b344455 上发现 wheel 限制失败的说明误导，后续明确展示真正缺 wheel 的包，并说明这是试验限制，不能推出 Python/版本冲突。对其提出的间接依赖过度固定风险，先用真实离线 wheel 解析复现失败，再改为只固定依赖图之外的包。pip/uv 配置文件被忽略、环境索引变量仍有效的边界已写入步骤，避免把该试验冒充用户原始安装配置。
