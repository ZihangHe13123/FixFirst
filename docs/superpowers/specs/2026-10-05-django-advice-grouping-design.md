# 合并重复的 Django 配置建议

## 范围

六次开发复验的 Django MCP 会话有 77 个动作，其中 73 个是同一个设置建议。用户同意继续改进，并明确优先修这一通用缺口。此项只合并已确认的相同建议，不新增持久配置路线、不修改故障分类、规则文本、知识或模型。

## 方案

只按标题合并会误合不同环境和配置。按故障大类合并也会误合“缺 settings”与“初始化顺序”。采用严格相同的配置证据和完整修复动作作为键，仅处理已由 P86/Django 机制证据授权的动作。

键包含同一设置机制、完整配置候选与未解析来源、插件状态和实际 argv，并要求标题、解释、验证、动作类型、检查目标、命令、声明修改及修复目标相同。不完整证据和其它规则动作保持原样。

合并时保留全部 issue_ids、reason_refs、preconditions、rule_ids；不删除故障或事实。使用组内最大 goal_impact / evidence_rank、最小 cost。保持首个动作 id 与位置，随后仍走原阻塞检查和排序。不同设置、不同命令、不同机制不合并。

## 验收

1. 真实已完成会话离线重放：73 条 P86 建议变成一条，覆盖原来的全部故障和理由；诊断、事实、故障总数和建议文本不变。
2. 相邻负例：相同标题但不同设置候选、机制、argv、插件状态或修复字段，不合并；缺证据、其它规则不合并。
3. 组内优先级保留最高影响，前置条件全部保留；重复执行规划结果稳定。
4. 三个知识测试、Django 定向测试、完整测试与 Ruff。若产品模块绑定使 owners 收据过期，执行原验证器重生成，不能手工粘贴摘要。

不运行模型、不读取保留数据。此改进只说明输出去重，不能将这次已见 Django 重放当作工具收益提高的证据。
