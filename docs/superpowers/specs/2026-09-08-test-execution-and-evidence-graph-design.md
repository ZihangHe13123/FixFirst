# 测试执行与证据知识图谱

用户目标为持续优化，并明确允许扩展功能。延续已授权的本地工具设计，本轮不另外请求重复批准。

## 选择

可优先做可视化外壳、继续扩充相似模板，或补强诊断覆盖与课程缺口。本轮选择第三条：当前系统不处理测试执行失败，也不能证明已覆盖课程三个技术组。前两条本身无法解决这两个缺口。

## 测试执行

新增 `pass_tests` 目标和 `pytest_run` 工具，保持原有 `pytest` 收集入口的含义。默认轻量扫描仍不执行测试体；选用新目标或明确指定新检查才执行。测试结果记录 setup/call/teardown 各阶段、选中节点、跳过和预期失败。

支持重跑已观察到的测试节点。传入的节点必须来自当前解释器的执行记录、位于项目目录内，并作为独立 argv 参数传递。完整通过需要测试完成证据；选择性重跑只能更新有明确通过证据的节点，不能证明全项目目标。跳过、xfail、删除测试、超时、不完整事件不能关闭旧失败。

问题组可能包含多个节点。组内部分节点通过时保存覆盖说明，只有全部成员得到验证才能关闭；后续完整结果应更新分组成员并避免重复展示。pytest 收集和执行的历史保持区分。

规则新增执行阶段到目标的关系，以及断言 / 执行异常的处理行动。分类器新增可观测特征，同时兼容旧 JSON 模型，预测仍独立于证据。HTML 显示各阶段和结果计数，菜单支持目标选择与失败测试重跑。

## 知识图谱

采用显式、有类型的实体和三元关系：Goal、Action、Fact、Issue、Event、Run。关系包括 recommends、addresses、justified_by、inferred_from、has_event、observed_in、supported_by、evaluated_by。只从实际记录与规则轨迹建边，不从文本相似度推断因果。

提供 `graph` 导出和 `ask` 中文查询：当前目标有哪些问题、为什么推荐某行动、某问题依据是什么。查询基于实体匹配与图遍历，返回实体及来源路径；无法匹配的问题明确提示支持范围，不生成未经支持的回答。

HTML 报告增加图谱关系浏览与查询，分享导出保留脱敏后的图数据。课程证据由具体图实体、关系、查询、产品集成和回归检查共同支撑，而不是仅在报告写“使用知识图谱”。

## 验证

真实执行健康测试、断言失败、fixture setup/teardown 失败；两个独立失败先只恢复一个、选择性重跑、再完整恢复。覆盖 skip/xfail、失败后删除节点、收集通过但执行失败、错环境、不完整报告及同组部分通过。保留 v0.1 已有案例和模型的读取兼容性。

知识图谱验证每条边端点存在、关系类型合法、查询结果能追溯到真实 Run、未知问题不编造，且脱敏导出没有原个人路径。新增实际故事报告和验收结果，记录仍未证明的自然项目泛化及真人收益。
