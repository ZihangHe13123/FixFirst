## 改了什么

| 验收项 | 处理 |
|---|---|
| O1 | 移除程序目标的旧 P12 覆盖文字，程序、pytest、unittest 等目标共用导入路径建议。 |
| N1 / O2 | 在现有 root/src 索引之外单独记录有限的源码根候选；精确导入、唯一位置、当前失败和项目证据一致时才使用。 |
| N2 | 当前项目快照确认构建入口时，说明读取安装元数据的项目还可用同一解释器执行 `-m pip install -e .`。 |
| N3 | 接收对象明确超出观察边界时，保留树的原始输出，但不采用它来推定代码缺陷。 |
| N4 | 明确路径值需要引号，并保留已有 PYTHONPATH、解释器、参数和输入。 |

候选源码根不加入用于证明库遮蔽的 `local_modules`。有多个根、缺少完整环境、已有外部提供者、普通偶然同名文件、目录越界等情形继续保守处理。`tests/` 本身是包时，其中的 helper 仅对该目录里的失败导入提供路径建议。每个失败事件的引用还必须属于当前运行、节点、阶段和项目。

默认模型仍是同一个 81 特征 / schema 8 文件，SHA-256：
`189f712ea75bcb117f96aae879fd0c9bdab9ee6531475d1a95faf01ec2738d30`。
没有重训或调整树权重。新布局的特征现在能读到新增的本地路径证据。

剩余限制：

- **候选索引的上限与歧义**：当有界源码扫描得到的 Python 文件列表达到 2000 项时，新增候选导入根索引整体停用，以免把截断搜索当作唯一性证据。不是统计磁盘上所有 `.py`；原有根目录和 `src/` 模块识别仍保留。多根歧义、生产代码导入测试 helper、导入的旧日志等缺少授权证据的情形也继续给通用步骤。原始树仍可能显示错误的 `missing_dependency` 疑似线索，但不据此给路径或安装建议。
- **安装元数据的后续步骤**：第一次 P12 已提供可选安装路线；若只设置 PYTHONPATH，之后遇到项目自身的 `PackageNotFoundError`，第二轮仍可能只给通用审查文字。

- **测试 helper 的导入方式**：`PYTHONPATH=tests` 可使验收用例通过，但 `helpers` 与 `tests.helpers` 会形成不同的模块身份；当前文字未给出改用包内限定导入的另一条路线。
