# 小组讨论：报告草稿

当前是 v0.4 草稿，内容未完成，三位组员讨论和修改后再定稿。

- **结论怎么写**：核对修复率、效率和 H5 的限制，避免把构造题结果说成真实项目的普遍可靠性。
- **未覆盖情况怎么补**：主分析 18 题主要用已有机制；未覆盖环境题只有 2 道。建议先补一小批未收录接口、其它环境故障和证据不足的情况，检查误导建议、合理回退和额外开销。再选一批真实项目，选题时不按产品能否命中来筛选。规模和分工由小组讨论决定。
- **还缺什么材料**：真实用户研究、独立安装/Windows 验收、B12 第二阶段、B17、原 proposal、个人反思及提交包装。
- **怎么改稿**：每人直接标出对应章节和修改意见，讨论后确定谁补哪一项；个人反思由本人写。

新增测试尚未开始，已有正式实验的条件和结果保持原样。待办只需写清“做什么、谁负责、怎样算完成”。
