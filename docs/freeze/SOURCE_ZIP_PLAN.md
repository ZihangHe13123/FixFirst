## 2. 政策和目标绑定后再执行的打包步骤

以下为通用步骤，实际已执行版本与结果见[公开交付记录](PUBLIC_DELIVERY.md)。先保存完整目标提交号、源码版本、默认模型SHA、白名单SHA和操作者；确保清单及所列文件已在同一目标提交中。
`PACKAGE_SHA`必须是交付负责人确认的完整40位提交号，不能拿当前可变工作树或短版本字符串代替。

在仓库根目录使用已安装的开发环境执行标准库构建入口：

```bash
.venv/bin/python scripts/build_source_zip.py --revision 完整40位提交号 --output output/FixFirst-candidate-source.zip
```

该入口读取指定提交里的白名单及源码，核对每个文件为普通Git blob、ZIP成员完全相同、文件字节逐项核对（仅接受仓库声明的Windows脚本CRLF转换，收据分列原blob与包内摘要）、元数据与模块版本均为0.7.0、模型符合B5固定摘要。已存在的输出文件会拒绝覆盖。
输出ZIP与相邻的`.zip.receipt.json`：后者记录实际源码提交、版本、ZIP/白名单/模型及每个文件的SHA256。再次从同一提交构建到新路径可核对ZIP字节一致。构建过程不运行测试、不安装环境、不训练模型。

压缩包按实际清单核对成员，保留包摘要和白名单摘要。不要压缩本机整个工作树，不用`.gitignore`代替成员白名单。
正式版本号、tag、push与公告是后续受控步骤，此命令不执行这些动作。安装仍走源码＋setup，不新增wheel/sdist/离线镜像交付要求。

## 3. 干净安装步骤（按具体版本记录执行）

1. 将上述ZIP解压到新的空目录；在Windows额外选含中文和空格的路径。记录包摘要、完整提交号、版本和系统/Python。
2. 确认解压目录没有带入`.venv`。在包含pyproject的目录按[候选简明指南](CANDIDATE_QUICKSTART.md)执行setup.sh或setup.ps1；首次依赖下载需要联网。
3. 记录安装输出/退出码、工具解释器与目标项目解释器。启动本地界面，按指南完成样例流程、命令复制、导出和从同一store重开。
4. Windows按[交接步骤](WINDOWS_HANDOFF.md)和[空白收据](ACCEPTANCE_RECEIPT_TEMPLATE.md)实际记录；未执行、未覆盖和阻断保留，不预填PASS。
5. 全量pytest/Ruff回归使用明确绑定同提交且包含公开开发fixture的开发工作区；当前安装清单没有这些材料时记NOT COVERED，不将“未发现tests”当成通过。
