# 全员任务

## X1 周会

- **时间**：每周一晚上 30 分钟；周四快速对一次进度，10 分钟。
- **议程**：
  1. 每人各说一分钟：上周完成了什么、这周做什么、卡在哪里（对照自己的 Issue）；
  2. 需要一起决定的事；
  3. 下周的截止日期。
- **记录**：会后由轮值的人在置顶 Issue 里写三行——决定了什么、谁做、什么时候交。
- **冻结前的注意**：A 和 C 在会上只报数字和进度（例如"标了 8 个，版本问题 4 个"），不说项目名。

## X2 系统视频（5 分钟，真人旁白）

| | |
|---|---|
| 负责 | B 主讲；A 录数据和实验部分的旁白；C 可以参与 |
| 时间 | 脚本 10/19；录制 10/20–10/23；成片 10/24 |

课程要求的内容是 **System Design** 和 **Technical explanation of use cases**。建议结构：

| 时间 | 内容 | 谁讲 |
|---|---|---|
| 0:00–0:30 | 系统要解决的问题，一句话讲清楚 | B |
| 0:30–2:00 | 架构：检查 → 分组 → 证据 → 知识 → 规则 → 排序 → 验证；三种技术各负责什么 | B |
| 2:00–3:00 | 一次判断的完整过程（collections.Mapping 的例子，从证据到规则再到来源） | B |
| 3:00–4:15 | 数据和实验：生成数据、留出的真实项目、基线对比、用户研究的主要结果 | A |
| 4:15–5:00 | 局限和下一步 | B |

录制方法和 [C8](C8-promo-video.md) 一样。**不允许 AI 生成的讲解语音。**

## X3 个人反思和同伴评价（每人各自提交）

| | |
|---|---|
| 截止 | 10/24 前写好；10/25 23:59 前每人自己提交到 Canvas 的 [Individual] Project Peer Evaluation |
| 必须自己写 | 不要让 AI 代写 |

- **个人反思**，1 页，照课程示例的三个问题写：
  1. 我对项目的个人贡献；
  2. 我学到的最有用的东西；
  3. 这些知识和技能能用在哪些别的场景或工作中。
- **同伴评价表**：按 Canvas 上的表格填。
- **从现在开始记工作日志**：每做完一件事，在自己的笔记里记一行（日期、做了什么、对应的 PR 或 Issue 链接）。写反思时直接用，也能对上 GitHub 上的提交记录。

## X4 打包提交

| | |
|---|---|
| 负责 | 组长；其他人 10/24 前把自己负责的文件交齐 |
| 截止 | 10/24（六）打好包，全员检查；10/25（日）23:59 前组长上传到 Canvas 的 [Group Leader] Project Deliverables |

课程要求准备四样东西，按命名规则命名，再压成一个 zip：

| 文件 | 内容 | 命名示例（按我们的信息替换） |
|---|---|---|
| `member-github.txt` | 组名；每人的全名（和学生证一致）；学号；仓库链接 | 放在 zip 里 |
| 两个视频 | 宣传视频、系统视频 | `IRS-PM-<开课日期>-<班级代码>-GRP-<组名>-FixFirst-promotion.mp4`，以及 `-system.mp4` |
| 仓库 zip | 在 GitHub 上下载：Code → Download ZIP（C6 合并、最终标签打好以后下载） | `IRS-PM-<开课日期>-<班级代码>-GRP-<组名>-FixFirst.zip` |
| 报告 PDF | 正文和全部附录 | `IRS-PM-<开课日期>-<班级代码>-GRP-<组名>-FixFirst-Group-Report.pdf` |

把以上四样压成一个 zip，文件名按规则写成 `IRS-PM-<开课日期>-<班级代码>-GRP-<组名>-FixFirst.zip`。`<开课日期>`、`<班级代码>`、`<组名>` 由组长在 Canvas 上核对后统一填写。

上传前检查：

- [ ] 报告附录齐全：proposal、系统功能和 MR/RS/CGS 课程知识的对照、安装和使用指南
- [ ] 两个视频都不超过 5 分钟，旁白都是真人录的
- [ ] 仓库 zip 解压后，按使用指南能装起来
- [ ] `member-github.txt` 里的名字、学号、链接都核对过

## X5 考试准备（11 月第 1–2 周）

每个人都要能讲清楚系统，至少能完整讲这三个例子：

1. 一条规则从证据到结论的过程：D02 和 `collections.Mapping`；
2. 留出测试里的一个项目：FixFirst 说了什么，为什么对或者不对；
3. 用户研究或基线对比的主要结果，以及它的局限。

准备方法：

- 亲手跑一遍自己负责的脚本；
- 重读[《FixFirst 技术原理详解》](../技术原理详解.md)里和自己相关的章节，特别是第 12 节的追问汇总；
- 周会上互相提问。
