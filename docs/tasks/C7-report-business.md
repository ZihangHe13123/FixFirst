## 写哪几节（英文，合计约 5–6 页）

### 1. Business case（约 1.5 页）

- **痛点和数据**：
  - PyDFix 重建的 2,702 个真实构建里，1,921 个（71.1%）因为依赖错误无法复现，出处见 `docs/DATA_SOURCES.md`；
  - 试调研里，13 个开源项目按自己的说明安装后，有 12 个的测试跑不通（`docs/GENERALISATION.md`）；
  - Python 每年发布一个新版本（PEP 602），旧的模块和 API 会被陆续删掉。
- **谁会用**：
  - 接手旧项目的开发者；
  - 课程里的学生和助教；
  - 复现论文代码的研究人员；
  - 给开源项目新贡献者排错的维护者；
  - 有很多遗留 Python 系统的企业。
- **价值**：
  - 更快找到根因；
  - 不乱改代码（不删测试、不瞎升级）；
  - 在本地运行，代码不出机器；
  - 每条建议都能追溯到证据和官方文档；
  - 修好要经过真实检查才算。

### 2. Market research（约 1.5 页）

写一张对比表，列出现有的做法和工具：

- `pip check` / pip 的依赖解析；
- pipdeptree；
- Dependabot / Renovate（让依赖保持最新，不负责诊断失败）；
- tox / nox（管理测试环境）；
- IDE 的检查（PyCharm、VS Code）；
- 通用 AI 助手（ChatGPT、GitHub Copilot、Claude Code 等）。

每个写：它做什么、不做什么、和 FixFirst 的区别。重点讲清楚和 AI 助手的差别：FixFirst 在本地运行，结论可追溯，修好要经过验证，而且可以作为 MCP 工具给 AI 助手用，两者是互补的。

学术上的相关工作由 A5 的文献综述负责，这里只写产品和工具，两节之间互相引用。

### 3. Pricing（约 0.5 页，宣传视频也要用）

给出一个清楚的定价方案，并说明理由。下面是一个可以直接讨论的起点，数字由组里商定：

| 版本 | 内容 | 价格 |
|---|---|---|
| Community | 本地命令行和网页界面，开源 | 免费 |
| Pro（个人） | 每月更新的知识库（新版本删掉了哪些名字）、发布版本搜索加速、导出报告 | 每月若干新元 |
| Team | Pro 的全部功能 + CI 集成、团队共享的规则和知识库 | 按席位计费 |
| Education | 给课程和助教用的 Team 版 | 免费或优惠价 |

引用竞品价格作参考时（比如 Copilot 的个人版），写明查询日期和来源链接。

### 4. User study（约 1.5–2 页，在 C3 之后写）

由 `docs/user-study/RESULTS.md` 改写：

- 方法：设计、参与者、任务、指标、平衡顺序；
- 结果：完成率、用时、SUS、错误声称"好了"的次数、访谈里的意见；
- 讨论：和 proposal 的目标对照，结果不好也要解释原因；
- 效度威胁：人数少、学习效应、任务是人为构造的、实验员是组员。
