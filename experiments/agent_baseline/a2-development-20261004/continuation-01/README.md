原登记为 [PR #73](https://github.com/ZihangHe13123/FixFirst/pull/73)，提交 `232f2ba6d12854439ba61b5d6da89ca104be7340`，在推理开始前已合并。

## 为什么停下

Qwen3.6 的 cachetools 三组冒烟已完成并通过校验。下一批 Gemma 在端口检查处停止，尚未启动服务/框架进程，也未发送模型请求；主体对照完成数为 **0**。已有3行保留，自己的服务、框架进程和防睡眠断言均已清理。

原启动器在服务关闭后马上用不带 `SO_REUSEADDR` 的 bind 判断端口可用性。独立随机端口实验复现了：TIME_WAIT 时普通 bind 失败、REUSEADDR bind 成功；活 LISTEN 时两种 bind 都拒绝。父批次失败瞬间没有保存 socket 表，因此 TIME_WAIT 是吻合证据的解释，**不是声称当场观察到了原端口的 TIME_WAIT**。事后原端口没有监听。
