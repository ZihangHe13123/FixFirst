# 冒烟复核后的主体入口

沿用原登记的两项目、三模型、三组和78次计划。此处记录事前允许的工具能力补查及主体启动条件，产品仍为 `804cc3c455061517cbc5edb21a9fe4b66626b453`，协议仍为 `3bf846ae`。

## 为什么需要人工复核

Gemma 的 baseline 实际调用了 `run_command`；facts 调用了 `observe`，mcp 调用了 `diagnose`，之后三组都以 `stopped_without_tool` 结束。后两组没有继续调用基础工具，因此自动冒烟覆盖门不通过。原行、终止原因、修复结果和覆盖缺口全部保留，不补跑。

原登记提交 `232f2ba6` 的 PROTOCOL 已在第一次推理前写明：模型未调用可选工具时保留行为观察，必要的工具链能力可另做明确的无模型核查。

独立 fake 脚本在三组各运行一次，实际验证了命令执行、读写与回读断言，以及 facts/MCP 报告；三行均正常判分和清理。它只证明工具链可用，不能证明 Gemma 会修复任务，也不进入真实模型统计。诊断长解释仍是产品原有摘要，未另测 `explain`。

## 主体启动条件

- 两批真实冒烟共9行完整、身份一致、服务全部清理，且主体从未派发。
- 真实覆盖缺口必须恰好为 Gemma facts/mcp 未使用基础工具这两项；任何额外缺口均拒绝。
- 原 `SMOKE_GATE.json` 保持 `passed=false`；另存 Codex 事前审阅的条件规则、完成后的机器核验和证据摘要，不声称提前人工审过未来记录。
- 新入口只执行全新78次主体，不重新调用冒烟，不改提示、解码、预算或任务。

`MAIN_ENTRY_RULE.json` 先固定条件与脚本摘要；`review.public.json` 和 `REGISTRATION.json` 在主体第一条请求前固定实际证据与核验结果。这仍是两个 A2 开发任务的描述性对照，不支持泛化结论。
