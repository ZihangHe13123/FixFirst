## 改了什么

1. **异常来源。** 使用 probe 已记录的实际异常源文件，补回 pytest 隐藏的第三方库栈帧。用户回调抛出的错误仍归于用户代码；相对和绝对路径指向同一帧时不重复计数。
2. **NumPy 标量表示。** 字符串差异必须仅由标量包装产生，失败位置还要调用静态识别出的 NumPy 格式化函数。建议在构造输出时使用 `str(value)` 或 `!s`，保留预期数值和原测试。依据：[NumPy 2.0 发布说明](https://numpy.org/doc/stable/release/2.0.0-notes.html#representation-of-numpy-scalars-changed)。
3. **NumPy 标量类型提升。** JSON 序列化必须实际包含 NumPy 浮点标量和 Python 浮点数的混合运算。建议在 JSON 边界把计算结果转成 Python `float`，保留 JSON 数值类型。直接序列化 `np.float32` 的老问题不会因此被归为升级问题。依据：[NumPy 2.0 迁移指南](https://numpy.org/doc/stable/numpy_2_0_migration_guide.html#changes-to-numpy-data-type-promotion)。
4. **Pydantic 数字转字符串。** 要同时看到对应校验错误、库来源、版本上下文和直接定义的普通 BaseModel；严格、自定义或不完整的校验上下文不套用此建议。建议只转换受影响字段，再执行原测试。依据：[Pydantic V2 迁移指南](https://pydantic.dev/docs/validation/latest/get-started/migration/#validator-behavior-changes)。
5. **判断强度。** 新的兼容性判断标为假设。普通 ValidationError 不再仅凭旧的版本记录或声明下限被 H06/H08 推成版本问题。P62 的说明也明确：声明下限不能证明项目曾在哪个版本上运行成功。

## 复现

用 Python 3.12.14 的独立虚拟环境安装项目开发依赖，scikit-learn 固定为 1.9.0。生成时主要库版本在 `data/manifest.json`，完整环境在 `data/environment.json`。

回放不会执行案例或调用模型服务；输出目录必须是新目录：

```bash
.venv/bin/python experiments/core_diagnosis/replay.py \
  --train examples/diagnosis-dataset \
  --dataset experiments/core_diagnosis/development-2026-09-30/data \
  --output workbench/core-replay-after
```

旧实现使用同一个解释器和脚本，将 `PYTHONPATH` 指向独立检出的 `11bbe7e` 的 `src` 目录，另选一个输出目录。脚本会记录实际导入实现的 Git 提交及源码哈希。

验证真实修法和反例：

```bash
.venv/bin/python -m pytest tests/test_behavior_diagnosis.py -q
```

## 仍然缺什么

- 独立真实项目上的根因和第一步效果，继续按原留出流程验证。
- 决策树自身的提升：这轮未见收益。后续需要丰富可观察特征，以及按项目/故障来源分组的人工确认开发数据。
- 静态识别只覆盖本轮明确支持的简单调用和模型定义；动态别名、复杂封装和自定义校验可能保留原来的通用建议。
- 这些规则是在看到开发案例后设计的。30/30 不能用作无偏泛化结果，也不能证明整个产品已经达到最终性能要求。

本轮结束条件是交付可复核的核心改进和对照记录；B5 冻结、正式实验及其他辅助任务的完成状态不因此改变。
