# Public data: PyDFix and BugsInPy

The proposal named two public sources. This folder records what each one actually contains
and which part of it FixFirst can use. Everything here is regenerated by

```bash
.venv/bin/python scripts/collect_public_data.py     # about 30 seconds, ~1,100 downloads, cached
```

which reads both sources at fixed commits, executes nothing and installs nothing.
`pydfix/labels.csv` is the only hand-edited file; the script creates it once and never
overwrites it.

## PyDFix (Mukherjee, Almanza and Rubio-González, ISSTA 2021)

Source: [ucd-plse/PyDFix](https://github.com/ucd-plse/PyDFix/tree/b276d79e7aff1993280e80bad97a8b8a08e6661f),
BSD-3-Clause (notice in `pydfix/LICENSE`). PyDFix rebuilt old Travis CI builds from BugsInPy
and BugSwarm, flagged the ones broken by dependency errors, and tried to repair them by
pinning versions. The paper reports that 1,921 of the 2,702 builds it rebuilt (71.1%) no
longer reproduced because of dependency errors
([ISSTA 2021](https://dl.acm.org/doi/abs/10.1145/3460319.3464797)).

**What is available.** Two analysis tables (1,927 rows) with the flagged error line, the
candidate packages and PyDFix's repair outcome. The rebuilt logs themselves are not in the
repository; recreating them needs Docker, Ubuntu 18.04, the BugSwarm images and the original
Python 2.7–3.8 environments.

**What fits FixFirst** (`pydfix/summary.json`):

| Rows by error kind | BugsInPy table | BugSwarm table |
|---|---|---|
| Import error (`No module named`, `cannot import name`): **in scope** | 126 | 328 |
| `setup.py` / `build_ext` build failure | 158 | 648 |
| Python version requirement (Python 2.7/3.4 era) | 0 | 347 |
| `pip install` command failed | 32 | 28 |
| `TypeError` / `AttributeError`, other | 0 | 43 |
| Empty error line | 190 | 27 |
| **Total** | **506** (7 repositories; pandas alone 338) | **1,421** (33 repositories) |

The 454 in-scope rows are repeated builds of the same few failures. `pydfix/cases.csv` keeps
one row per repository and missing name: **22 distinct cases in 10 repositories** (7 of them
come from one Twisted CI job). For each case it keeps an excerpt of the error, PyDFix's
candidate packages (raw, including its own parsing noise), its repair outcomes and, when it
succeeded, the versions it pinned. Examples: searx's `cannot import name ImmutableDict`
(Werkzeug), scikit-learn's `No module named 'scipy'` (192 rows), black's missing `click`.

**Intended use.** A small external, text-only check: give FixFirst the error excerpt and
compare the cause and package it names with the case's label. Only the error line is
available, not the environment, so this measures parsing and knowledge-base coverage rather
than the full diagnosis. Following the proposal, PyDFix's pinned versions are reference
material, not the answer key: label each case in `labels.csv` (root cause, who labelled it,
who reviewed it) **before** running FixFirst on it.

## BugsInPy (Widyasari et al., ESEC/FSE 2020)

Source: [soarsmu/BugsInPy](https://github.com/soarsmu/BugsInPy/tree/11c5f1eea954a42132cfd06bf257766a7963e0fd).
The repository has no licence file, so this folder stores only facts about each bug (project,
Python version, commits, test file) and links, never BugsInPy's own files; the script fetches
those when needed.

**What is available.** 501 real bugs in 17 projects, each with a buggy commit, a fixed commit,
a failing test and a pinned package list. All are defects in the project's own code, so every
bug belongs to FixFirst's *code defect* class.

**What it takes to run them here** (`bugsinpy/summary.json`, `bugsinpy/bugs.csv`):

| | Bugs | Projects |
|---|---|---|
| Python 3.8, which uv installs on this Mac | 320 | black, fastapi, luigi, matplotlib, pandas, PySnooper, sanic, scrapy, spacy (1) |
| Python 3.6/3.7, which needs Docker | 181 | ansible, cookiecutter, httpie, keras, spacy, thefuck, tornado, tqdm, youtube-dl |
| Tier 1: nothing to compile | 70 | PySnooper 3, cookiecutter 4, tqdm 9, tornado 16, youtube-dl 38 |
| Tier 2: small C extensions only | 53 | fastapi 16, httpie 5, thefuck 32 |
| Tier 3: numpy/scipy/pandas/TensorFlow-sized stacks | 378 | the rest; pandas alone is 169 |

Tiers count pinned packages that have no Apple Silicon wheel for their 2019–2020 release. The
pinned lists are whole environment freezes, so a single failing test may need fewer. No bug
has been reproduced yet.

**Intended use.** Not the diagnosis experiment (every label would be *code defect*), but:

1. **Verification**, as planned in the proposal: at least 8 bugs from at least 4 projects,
   admitted only if the test fails on the buggy commit and passes on the fixed one. FixFirst
   must close the issue only after the same-scope check passes on the fixed commit, and must
   not close it after a partial rerun, a skip or an imported log. Tier 1 alone has 70 bugs in
   5 projects.
2. **Not blaming the environment**: on genuine code defects FixFirst should not recommend
   installing, upgrading or pinning packages. This measures false environment diagnoses, which
   the generated dataset cannot.
